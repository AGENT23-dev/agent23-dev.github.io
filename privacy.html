Privacy policy — Hermes Agent

Personal automation client operated on a single Mac mini by its owner.

Last updated 29/10/2026.

1. Who this policy covers

Hermes Agent ("the application") is a private software client installed and run by one individual, referred to here as "the operator", on a Mac mini computer that the operator owns. The application serves exactly one Google account: the operator's own (agent23.dev@gmail.com). It has no other users, no sign-up, and no server-side service. This policy explains what the application does with data obtained from Google APIs.

Data controller and contact for all privacy matters: agent23, an individual established in Belgium — agent23.dev@gmail.com.

2. What Google data the application accesses

Only after the operator grants consent through Google's OAuth 2.0 consent screen, and only for the operator's own account, the application may access:

  • Gmail — message headers, bodies, attachments, labels; and the ability to send mail and change labels on the operator's instruction.
  • Google Drive — file metadata, file content, folder structure; and the ability to create, upload, modify, trash files and to share a file with a recipient named by the operator.
  • Google Docs and Google Sheets — document and spreadsheet content; and the ability to create documents and spreadsheets and to write content into them.
  • Google Calendar — event details; and the ability to create or delete events.
  • Google Contacts — the operator's contact names and email addresses, read-only.

The application does not access Google data belonging to anyone other than the operator, and does not aggregate data across users.

3. How the data is used

Data is used solely to carry out tasks the operator requests in a conversation with the assistant, for example: finding a document, summarising a message, creating a spreadsheet, or sharing a file with a named recipient. There is no other purpose.

The application does not:

  • sell, rent, license or otherwise transfer Google user data to any third party;
  • use Google user data for advertising, profiling or marketing;
  • use Google user data to train or improve machine-learning models;
  • allow humans to read Google user data, except where the operator themselves reads it, or where required by applicable law.

4. Processing by a language-model provider

The assistant is powered by a large language model. To answer a request, the specific content needed for that request (for example the text of one document, or the body of one email) is transmitted over TLS to the language-model API provider used by the operator at the time — currently DeepSeek — acting as a processor on the operator's behalf, and only for the purpose of producing the response. No Google user data is transmitted to any other third party, and none is retained by the operator beyond the points described in section 5.

5. Storage and retention

  • Tokens. The OAuth access and refresh tokens are stored in a single file on the operator's own Mac mini, readable only by the operator's user account (~/.hermes/google_token.json, mode 0600). They exist for as long as the access grant exists.
  • Working data. Content retrieved from Google APIs may be held in memory during a task, and may be written to the operator's own local disk when a task requires a local file (for example a downloaded document). It is not copied to any server operated by this project, because no such server exists.
  • Logs. Local logs record which actions were performed (for example "file shared"), not the content of Google user data.
  • Retention. Nothing is retained after the operator deletes it locally or revokes access. Revoking access at myaccount.google.com/permissions invalidates the stored token immediately.

6. Security

Access is granted through Google's OAuth 2.0 flow with PKCE, with the minimum scope set needed for the features described above. Tokens are held locally with owner-only file permissions on a single machine that is not exposed to the internet. No Google credentials are ever stored outside that machine.

7. Google API Services User Data Policy — Limited Use

Hermes Agent's use and transfer to any other app of information received from Google APIs will adhere to the Google API Services User Data Policy, including the Limited Use requirements.

8. Your rights

The only data subject is the operator, who already controls the machine and the Google account. The operator may, at any time: revoke the application's access in the Google account settings; delete the local token file; or delete any local copies of retrieved content. Because the operator is also the controller, no separate request procedure is needed. Questions can be sent to agent23.dev@gmail.com.

9. Children

The application is not directed at, and is not made available to, anyone under 16.

10. Changes to this policy

Any change to how the application handles Google user data will be published on this page with a new "last updated" date. Because the application has a single user, changes take effect for that user on publication.

Operated by agent23, Belgium. Contact: agent23.dev@gmail.com.
